# DIKIT — Product Requirements Document (PRD)

**Product name:** Dikit  
**Document version:** 1.0 — Initial approved direction  
**Date:** October 31, 2026  
**Platform:** Windows desktop (Windows 11 first)  
**Product type:** Personal, offline-first sticky notes and screenshot pinboard  
**Development environment:** Visual Studio Code  
**Proposed implementation:** C#  + WPF + .NET 10 LTS  
**Status:** M1 implemented on `devin/dikit-v1-ios-notes` (pending Windows build verification); M2–M4 planned

## 1. Product Summary

Dikit is a lightweight, offline Windows desktop sticky-note application that lets a user capture ideas, screenshots, web links, checklists, and quick reference material as independent, customizable note windows. Notes persist locally, reopen after the user signs into Windows, and restore their sizes, positions, and chosen themes. No account, cloud database, internet connection, or background server is required for core use.

**Product promise:** "Stick your thoughts, your way." (working tagline)

## 2. Problem Statement

Typical sticky-note apps focus on plain text or require repeated manual launching and rearranging after a restart. General-purpose productivity tools can be cumbersome when the user needs to keep a screenshot, reference URL, or short checklist visible alongside other desktop applications. The user wants notes that feel personal, remain organized, and return in the same layout whenever Windows starts.

## 3. Goals and Success Measures

1. Capture a new note in no more than two user actions after the application is running.
2. Support text, pasted screenshots, clickable HTTP/HTTPS links, and checklists in an individual note.
3. Persist note content and styling automatically, without requiring a Save button.
4. Restore all open notes with their geometry and themes when the app restarts or Windows signs in.
5. Function with no network connection for all core workflows.
6. Offer personal themes, including reusable presets and per-note overrides.
7. Keep the user interface responsive with 10–20 typical notes open.

**Proposed performance targets (to test, not guarantees):** Launch to usable interface within ~3 seconds on the target laptop; autosave settled within 1 second of the last edit; no observed data loss after normal shutdown or application restart; measure RAM at 1/10/20 notes and optimize based on results. Do not set an unverified universal RAM limit.

## 4. Target Users and Environment

- Primary: a student/developer who works across VS Code, browser, terminal, and project-management apps.
- Secondary: any Windows user wanting visual, persistent, locally stored reminders and reference notes.
- Windows 11 is the initial target; Windows 10 LTSC/Enterprise compatibility can be evaluated separately.
- Single device, single local Windows profile, no collaboration or synchronization.

## 5. Scope

### 5.1 MVP — Must Have (P0)

| ID | Requirement | Acceptance criteria |
|---|---|---|
| F-01 | Create, edit, duplicate, and delete a note | Each operation updates the UI and persisted data; deletion asks for confirmation or has recovery |
| F-02 | Text content | Text can be inserted/edited and is saved automatically |
| F-03 | Screenshot/image capture | After Win+Shift+S, user can paste from clipboard into a note; app stores its own copy locally |
| F-04 | Clickable website links | HTTP/HTTPS URLs can be created and opened in the user's default browser; invalid/unsupported schemes are not executed |
| F-05 | Checklists | Checkbox state and text persist across restarts |
| F-06 | Independent note windows | Notes can be dragged, resized, and minimized individually |
| F-07 | Window state restoration | Position, dimensions, open/closed state, topmost state, and theme restore after relaunch; off-screen notes are recovered on-screen |
| F-08 | Automatic local persistence | Notes save on changes using debouncing and safe replacement, with recovery on failed writes |
| F-09 | Personal themes | User can choose a preset and customize background, foreground, accent, font, corner radius and opacity; preview changes |
| F-10 | Per-note customization | Each note can inherit a global theme or use its own override |
| F-11 | Auto-start with Windows | User can opt in/out; only one instance launches; no UAC/admin rights required |
| F-12 | System tray / note manager | Show all notes, create note, restore hidden notes, open settings, and explicitly Quit |
| F-13 | Offline operation | Core features work when Wi-Fi/network is off; no cloud account or backend |
| F-14 | Data resilience | Normal close, restart and sudden app termination do not corrupt all notes; local backups exist |

### 5.2 Should Have (P1, after functional MVP)

- Search notes by text, title and link.
- Keyboard shortcuts for new note, quick hide/show, and paste image.
- Export/import notes and themes (ZIP/JSON/Markdown plus assets).
- Background image option per note; user-chosen fonts (locally installed).
- Multiple named workspaces (e.g., Coding, School, Personal).
- Note templates (quick link, screenshot board, checklist, snippet).

### 5.3 Could Have (P2)

- Rich formatting (bold, headings, inline code, full Markdown preview).
- Snippet syntax highlighting.
- Theme sharing as a small portable JSON file.
- Optional reminders (local notifications only).
- Snap-to-grid and group notes on the screen.

### 5.4 Explicitly Out of Scope for MVP

- Accounts, cloud sync, login, browser/mobile versions, shared notes or real-time collaboration.
- AI chat, OCR, internet fetching, remote backups, and analytics/telemetry.
- A true wallpaper-embedded desktop layer that remains behind all windows or survives Win+D as desktop content. Standard movable note windows are the MVP. An always-on-top option is allowed.
- Native Markdown editor with every document formatting capability.
- Replacing a full project manager or knowledge base.

## 6. Main User Flows

**Flow A — First launch:** Run Dikit -> show a short welcome note and settings access -> user chooses theme -> note data folder is initialized -> user may opt in to launch at sign-in.

**Flow B — Quick note:** Tray icon or shortcut -> Create note -> type -> autosave -> move/resize -> close/hide. Closing a note does not delete it.

**Flow C — Screenshot:** Windows Snipping Tool (Win+Shift+S) -> copy screenshot -> select note -> paste -> save a compressed/encoded image copy as a local asset -> render thumbnail or inline image -> reopen successfully offline.

**Flow D — Reference link:** Type/paste URL -> render clickable link -> click -> Windows opens default browser (requires internet only when the destination site does).

**Flow E — Personal theme:** Settings -> Theme Studio -> select preset / change colors, font, radius, opacity -> live preview -> save preset -> apply globally or to one note.

**Flow F — Restart:** Windows signs in -> Dikit launches if opted in -> reads manifest and note records -> recreates open windows -> clamps positions to currently attached monitor bounds -> restores appearance and content.

**Flow G — Recovery:** If a note file is invalid -> show a non-destructive recovery warning -> load most recent valid backup or isolate the broken note; never overwrite the only recoverable copy automatically.

## 7. User Interface and UX

- **Tray icon:** New note, All notes, Hide all, Restore all, Settings, Quit.
- **Note window:** Minimal titlebar, title field, editable blocks, color/theme button, pin/unpin, minimize/close. Resizable with a minimum width/height.
- **All notes view:** Lightweight overview with search and open/closed status; no mandatory dashboard at every launch.
- **Theme Studio:** Theme swatches, color pickers, font picker, radius, opacity, preview, Save as preset, Reset to default.
- **Preset themes:** Classic Yellow, Lavender, Matcha, Sakura, Midnight; all are editable.
- **Accessibility:** Keyboard-accessible controls, readable contrast options, DPI-aware rendering, tooltips, and visible focus indicators.

**Window behavior:** Notes are ordinary independent windows; a per-note Always on Top switch pins a note above other applications. Closing or hiding a note must not erase it. Full exit is a separate tray command.

## 8. Proposed Technical Architecture

**Stack:** C# / WPF (XAML) / .NET 10 LTS; .NET CLI with VS Code. Windows-native desktop only. Use MVVM for clean UI/state separation.

**Local storage:** JSON metadata per note, and copied image assets under `%LOCALAPPDATA%\Dikit`. No database required initially. Use `System.Text.Json`; do not add a SQLite dependency until querying or migrations justify it. (M1 implements per-note JSON, `manifest.json`, `app-settings.json`, and rolling backups under `backups/`.)

**Modules:**
1. `Models`: Note, ContentBlock, Theme, WindowPlacement, AppSettings.
2. `Views` and `ViewModels`: Tray, Notes, NoteEditor, ThemeStudio, AllNotes.
3. `Services`: NoteRepository, AssetService, ThemeService, WindowStateService, StartupService, BackupService, LinkLauncher, AppLifecycleService.
4. `Infrastructure`: local path resolution, safe atomic writes, schema migration, error logging (local only).

**Content model (implemented in M1):**

```json
{
  "schemaVersion": 1,
  "id": "note-uuid",
  "title": "Quick reference",
  "themeId": "lavender",
  "themeOverride": null,
  "blocks": [
    { "type": "text", "text": "Review API integration" },
    { "type": "link", "text": "Project board", "url": "https://example.org" },
    { "type": "image", "assetId": "assets/screenshot-01.png", "alt": "UI reference" },
    { "type": "checklist", "text": "Test new feature", "checked": false }
  ],
  "window": {
    "x": 160, "y": 140, "width": 340, "height": 400,
    "isOpen": true, "alwaysOnTop": false
  },
  "createdUtc": "2026-10-31T00:00:00Z",
  "updatedUtc": "2026-10-31T00:00:00Z"
}
```

**Proposed local data organization:**

```text
%LOCALAPPDATA%/Dikit/
  app-settings.json
  manifest.json
  themes/
    classic.json
    user-theme-001.json
  notes/
    <note-id>/
      note.json
      assets/
        screenshot-01.png
  backups/
  logs/
```

The directory is an implementation proposal. File paths must be generated and validated by the app, not directly trusted from user-provided note metadata.

## 9. Nonfunctional Requirements

- **Privacy:** No account, network calls, tracking or telemetry. Screenshot contents stay on-device.
- **Offline:** App launches and works with disconnected network.
- **Performance:** Optimize for moderate note counts; avoid Chromium/Electron and unnecessary background work. Test memory, responsiveness and cold startup on actual laptop.
- **Reliability:** Debounced autosave, temporary file + safe replacement on same volume, recovery and backups; avoid blocking the UI thread with image I/O.
- **Security:** Open only `http`/`https` links; no arbitrary command/file execution from pasted note text. Validate imported file sizes, file paths and formats. Never require admin rights for normal use.
- **Portability:** Notes can be backed up independently of the executable; future upgrades preserve prior schema.
- **Accessibility:** Usable at 125–200% display scaling, keyboard friendly, supports high-contrast themes.
- **Single instance:** Second launch should activate/show existing Dikit instance rather than create duplicate note managers.

## 10. Technical Risks and Decisions

| Risk | Impact | Mitigation |
|---|---|---|
| High RAM from many independent windows/images | Sluggish laptop | Resize thumbnails, lazy-load images, test 1/10/20 note workloads |
| Window positions become off-screen after unplugging monitor | Lost-looking notes | Clamp restored bounds to available monitors |
| Broken/incomplete save | Lost notes | Safe write + recovery backups + test forced termination |
| Large screenshots enlarge storage | Disk bloat | Limit file size/resolution; support image cleanup and attachments view |
| WPF RichTextBox serialization complexity | Fragile content editing | Start with typed content blocks; add full rich-text behavior only after storage model is stable |
| VS Code lacks WPF visual designer | More manual UI work | Edit XAML by hand and test live; Visual Studio IDE is optional |
| Windows startup integration | Unexpected auto-run | Make autostart opt-in, user-level, reversible |

## 11. Development Milestones

**M0 — Environment and Hello Window**
- Install .NET 10 SDK and VS Code C# tooling.
- Create WPF project with CLI; launch and debug a basic Dikit window.
- Initialize Git and repository README.

**M1 — Notes and persistence** *(implemented on `devin/dikit-v1-ios-notes`; build/runtime verification on Windows still pending)*
- Note model, JSON repository, create/edit/delete, autosave, and reload.
- One note window first, then multiple independently movable windows.
- Restore note geometry and handle off-screen coordinates.

**M2 — Images, links and checklists**
- Clipboard screenshot paste to local asset folder; image display/reload.
- Link blocks with safe HTTP/HTTPS opening; checklist blocks.

**M3 — Theme Studio**
- Preset theme system, colors, typography, radius, opacity and live preview.
- Per-note override and persistence.

**M4 — Startup, recovery and polish**
- Tray, explicit Quit, auto-start toggle, single instance.
- Backup/export, crash recovery, error states, keyboard navigation.
- Build/publish Windows release; validate offline and resource usage.

## 12. MVP Release Acceptance Checklist

- [ ] App starts from Windows executable without IDE or network.
- [ ] User can create at least 10 notes, move/resize them independently, and edit content.
- [ ] A pasted screenshot remains visible after app restart.
- [ ] A saved HTTPS link is clickable and opens in default browser.
- [ ] Checklists retain their state.
- [ ] Themes save; per-note overrides work after restart.
- [ ] App auto-starts only when enabled and restores the correct open notes.
- [ ] No note disappears off-screen when monitor configuration changes.
- [ ] Closing the main note window does not unintentionally delete stored content.
- [ ] Forced-close recovery test and local backup test pass.
- [ ] Core workflows function with Wi-Fi disabled.
- [ ] RAM, storage and startup time are measured and documented on the target laptop.

## 13. Development Setup

**Required:** Windows 11 computer; Visual Studio Code; .NET 10 **SDK** (not runtime only); Microsoft's C# extension, optionally C# Dev Kit; Git recommended.

**Not required:** Full Visual Studio IDE, Node.js, Rust, Docker, MySQL, internet connection during normal app use, cloud hosting.

**Official resources:**
- .NET 10 SDK: https://dotnet.microsoft.com/en-us/download/dotnet/10.0
- VS Code C# guide: https://code.visualstudio.com/docs/csharp/get-started
- WPF overview: https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview
- .NET CLI: https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-new

**Commands (PowerShell, once .NET 10 SDK is installed):**

```powershell
dotnet --list-sdks
dotnet new list wpf
cd "$HOME\Documents"
dotnet new wpf -n Dikit -o Dikit
cd Dikit
code .
dotnet run
```

Verify the generated `.csproj` targets `net10.0-windows` (or update it to that target if another SDK was selected). The first run should open the default WPF window. `dotnet build` checks compilation. WPF's graphical XAML designer is available in Visual Studio rather than VS Code, but code editing, building and basic debugging can be done in VS Code.

## 15. Open Decisions (not blockers to M0)

1. Default window-close behavior: hide note to manager vs remove window only. Recommended: close the note window but retain it in All Notes.
2. Image editing in MVP: paste/display/resize only; postpone image annotation.
3. Themes: per-note custom colors first; full wallpaper/background images later.
4. Backup frequency and retention: propose last 5 recoverable snapshots, tune after reliability tests.
5. Distribution: initial per-user framework-dependent build; optional self-contained portable `.exe` later, trading larger download size for no separate runtime installation.

---

**Bottom line:** Build a reliable, offline Windows note app first. Dikit's distinctive feature is a personal Theme Studio combined with persistent screenshot-and-link-rich notes—not a large project management system.
